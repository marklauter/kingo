## The work item

Two evaluators over the `SubjectSetRewrite` algebra, pure domain code in `Kingo.Closures`, the one project that references both `Kingo.Facts` and `Kingo.Theories` and the home of the fact-lookup port.

- **Contains** — the membership predicate behind the Check API: subject ∈ subjectset? A short-circuiting boolean walk; the hot path.
- **Expand** — one relation's rewrite tree, materialized single-level with respect to indirection. The audit, debug, and UI view.

First joint consumer of both aggregates, so expect it to pressure-test the algebra ([[the-first-consumer-forges-the-domain]]).

## Naming

- **`Contains`** is the domain predicate, set-first: `subjectSet.Contains(subject)` matches the ∋ reading ([[contains]]) and .NET's `set.Contains(member)`. Not `IsMember`, which re-inverts it.
- **`Check`** stays the service and API name, Zanzibar's reach word ([[grouping-the-apis-into-services]]).
- **`Kookie`** is Kingo's zookie (decided 2026-07-16): an opaque kernel value naming a point in the store's timeline — request-side a *floor* ("no earlier than this snapshot"), Decision-side the *pin* ("evaluated at this snapshot"). "Zookie" survives as the paper-facing alias ([[storage-versioning-design]]).
- **`Kingo.Closures`** is the interpreter project (decided 2026-07-18): "Acl" names the data structure ReBAC generalized away, and the interpreter answers membership in the derived closure, the set closed under the rewrite rules' derivation. "Reachability" was rejected because `!` and `&` make the derived set non-monotone, so the verdict is a function over several reachability questions rather than a reachability property itself.
- **The question value is `Fact.SubjectFact`, held putatively** ([[putative-fact]]; unified 2026-07-19, superseding the standalone `Query` type). `Fact` is a closed union over its member's shape: `SubjectFact` carries an `Identity`, `SubjectSetFact` a `SubjectSet`, `ResourceFact` a bare `Resource` — the exactly-specified factset shape (ruled 2026-07-21, [[resource-fact-case]]). The member seat is named `Subject` in every case, the paper's ⟨user⟩; the `Subject` wrapper record is dissolved, so subjects exist only as identifiers inside facts. The union moved from the subject seat to the fact itself 2026-07-19, dissolving the `Subject` DU and renaming `DirectSubject` to `Subject`. That refactor dissolved `Query`'s rationale, since replay from the wide DU needed a downcast and `SubjectFact` *is* the refined shape, so stored-versus-putative survives as stance, not type. *Query* survives as a seat name: `Decision.Query` is typed `Fact.SubjectFact`.

## Settled — domain-modeling interviews, 2026-07-16 through 2026-07-18

Kernels pinned with Mark before the clean-room session; treat them as constraints.

- **`Contains` answers one question: does the graph's derived closure contain this fact.** The algebra has no deny concept; `!` is set exclusion, another operator. Both truth values are first-class `Decision`s (clarified 2026-07-17), so "not included" is the false verdict, auditable and replayable, not an absence. "Authorized" and "denied" are the host's readings — including, under fail-closed policy, its reading of a failure, which has no Decision at all.

- **The question is putative and narrowed to check's shape: `Contains(SubjectSet subjectSet, Identity subject) → Result<Decision>`** (amended 2026-07-19, supersedes `Contains(Fact fact)`; `Identity` since the `Subject` wrapper dissolved 2026-07-21). An authentication token names a direct user, never a userset, so the narrowing is type-level: a subjectset-valued question is unrepresentable, not a modeled error; `Fact.SubjectSetFact` is storage vocabulary, not question vocabulary. The shape is closed under recursion — a stored subjectset member re-enters on the *set* side, `Contains(org/team:sales#member, anne)`, and the subject side never changes type. Neither `Fact` nor `SubjectSet` carries a `Parse` ([[deciding-which-types-parse-text]]), so no question arrives as text at this seat; the narrowing is enforced wherever the host adapter builds the pair. Host-edge design work, not settled here. `Contains` reads as an operation on `SubjectSet`, extension-method shape; the mechanics are design work because evaluation context (`Theory`, the pinned fact port, `TimeProvider`) is constructor state. The zookie is consumed at the host edge to pin the port, so the interpreter never sees one.

- **A subjectset-valued member is an expansion point, never a sought value** (amended 2026-07-19). `SubjectSetFact` exists so facts can store grants like `io/doc:x#viewer@org/group:eng#member`; the walk expands such members per the direct-membership requirement and matches the sought `Identity` by value equality at the leaves. No subset reasoning, no second semantics under `!`.

- **`Decision` carries exactly one question, the one judged, and none of the facts consulted** (amended 2026-07-19). Four slots: the question (typed `Fact.SubjectFact`, in a seat named `Query`), the verdict, the `Kookie` pin, the wall timestamp. The case type preserves the narrowing, since a `SubjectSetFact` cannot occupy the seat. Reproducibility comes from the store's multi-version history, not the payload.

- **The `Kookie` is the theory version; results carry no `TheoryVersion` slot** (ruled 2026-09-08, superseding the 2026-07-18 slot). The changelog versions each theory on its own, and a kookie selects one version of each: that selection is the catalog snapshot the evaluator reads ([[catalog]]). The evaluator's theory context is the catalog at the pin, not one injected `Theory`; each re-entry of the walk resolves its resource's namespace path against it, so a fact that crosses theories is ordinary. `TheoryVersion` (`src/Kingo/TheoryVersion.cs`) stays a kernel value of the changelog; encoding is [[storage-versioning-design]]'s.

- **Empty operator nodes are unrepresentable** (decided 2026-07-19). `Union.Create` and `Intersection.Create` refuse empty operand lists (`rewrite.union.empty`, `rewrite.intersection.empty`; implemented 2026-07-21, [[namespace-create-validation]]). The grammar cannot produce the shape, the Write API path could, and the conventional reading of an empty intersection, everyone a member, is an authorization hazard.

- **The depth bound is evaluator constructor config** (decided 2026-07-16; Contains only, since Expand never recurses, decided 2026-07-18). Injected alongside the port and clock, not carried in the theory document and not passed per call. `DepthExceeded` carries the bound it hit.

- **Operator error semantics are Kleene: the result is a function of operand values, never of evaluation order** (decided 2026-07-16). Error is the third value, and an *absorbing* value dominates it: `false` in `∩`, `true` in `∪`, and for `a ! b` (= `a ∩ ¬b`) both `a = false` and `b = true` absorb to `false`. Short-circuiting is sound exactly when the value in hand is absorbing, so the unobserved operand may be skipped or cancelled in flight; an error surfaces as `Result.Failure` exactly when it is *decisive*, meaning nothing absorbed it. The case already ruled, `a ! b` with `a` true and `b` errored → `Result.Failure` and no Decision, is this rule. Sequential, reversed, and parallel-with-cancellation evaluation yield the identical verdict; strict error-poisoning was rejected because the verdict would then depend on scheduling. The residual risk, a broken graph region hiding behind absorbing branches, belongs to the Write path and offline validation (theory cycles at construction, data cycles at write or sweep), not the hot path.

- **No `Decision.Empty`** (decided 2026-07-17). `Result<Decision>` failure carries no value property, so the failure channel *is* the no-answer case. Elsewhere, where a domain needs a no-answer value, prefer a domain singleton over null.

- **Factset traversal: exactly specified traverses, anything else is a modeled error** (decided 2026-07-16; amended 2026-07-21 to case-matching over the three `Fact` cases, no `...` sentinel, [[resource-fact-case]]). Evaluating `(parent, viewer)` on `io/folder:x` reads the facts under `io/folder:x#parent`, and each member is one of three shapes. A `ResourceFact` member (`io/folder:y#...`) is *exactly specified*: hop 2 recurses at `io/folder:y#viewer`. A `SubjectSetFact` member (`io/folder:y#viewer`) is *over-specified*. A `SubjectFact` member (`io/folder:y`, or `@user:anne`) is *under-specified*, offering no resource against which to pair the computed relation. The last two are modeled errors with distinct codes, in the family whose evaluation couldn't complete. Silent skipping was rejected because authorization outcomes must not change invisibly with data shape; override semantics for the over-specified case were rejected because they turn a data oddity into a permission redirect. The real guard belongs upstream: the Write path refuses wrong-shaped members on relations any rewrite uses as a factset's first element, making the evaluator's error a never-in-practice backstop. That guard is the Write service's work item; until it exists, the over-specified and under-specified member errors are the only protection.

- **The error taxonomy is settled** (decided 2026-07-16; the ill-shaped direct member added 2026-07-21): three families, nine conditions, ruled under [Error conditions](#error-conditions).

- **Fact/theory drift is closed at the write edge; undefined namespace or relation mid-walk is the backstop** (decided 2026-07-20; F8). Two Write-service invariants. *Facts can't lead the theory*: every fact write is validated against the current theory for namespace, relation, and member shape. *The theory can't abandon facts*: removing a namespace or relation is refused while live facts reference it, making removal a two-step migration, facts first. Whole-namespace and whole-theory deletion are the limiting case, and the changelog's deletion entry is terminal, since an empty `Theory` is unrepresentable per `theory.empty`. Evaluation and replay read the catalog and the graph at one `Kookie`, both artifacts versioned on the one store timeline. Fact rows carry created and tombstoned stamps below the port, never on `Fact`: stamps are not identity, and grant/revoke/re-grant is one value with two intervals. The theory is an append-only changelog whose version intervals close by supersession. Facts carry no theory version, because the abandonment guard makes valid-at-write-time imply valid ever since; storing one would be load-bearing only under multi-version evaluation semantics, which are rejected. Encodings and retention are [[storage-versioning-design]]'s; the invariants are Write-service work items ([[preventing-drift-between-facts-and-theories]]).

- **The pinned port exposes its snapshot token, and the token is the `Kookie` type itself** (decided 2026-07-19) — no distinct port token, no mapping layer. The interpreter copies the opaque value into the `Decision` without interpreting it, so the Decision is complete at birth. `Kookie` is stubbed at `src/Kingo/Kookie.cs`.

- **The result channel is `Result<Decision>` for Contains and `Result<Expansion>` for Expand.** Where no membership answer exists there is no `Decision`, not a Decision wearing an error flag; likewise no partial `Expansion`. Fail-closed is host policy, visible at the edge. Audit covers both channels: success serializes the result, failure serializes the error with the request envelope.

- **`Decision` carries two clocks, distinctly:** the snapshot token (logical time, *which* facts) and the wall timestamp from the injected `TimeProvider` (*when* evaluated). The stamp is taken at evaluation completion (decided 2026-07-20; F16), since the judgment exists when the verdict does; start time is envelope territory. It is never zookie-encoded — physical time correlates the decision with timelines outside the store, logical time replays it, and reading audit time out of a `Kookie` would breach its opacity.

- **`Expand` is single-level with respect to indirection, a graph walk of one step with edge choice left to the caller** (decided 2026-07-17; paper §2.4.5 adopted verbatim). One call materializes one relation's full rewrite tree, the union/intersection/exclusion structure with direct subjects at the leaves. Referenced subjectsets stay unexpanded leaves, `ComputedSubjectSet` included: it materializes as the leaf `resource#relation`, never as the referenced relation's inlined subtree (made explicit 2026-07-20; F10). Transitive closure is the caller's loop, paced edge by edge. Full closure was rejected for unbounded fact-driven work per call and because resolving `!` leaves drags Expand into re-implementing Contains. A depth-limit parameter was rejected because consumers must handle partially-expanded trees anyway, so it is the single-level contract carrying closure's cost profile, and it steps a whole level where single-level lets the caller choose per edge.

- **Caller identity is envelope, not `Decision`** (decided 2026-07-17). A field earns a slot on `Decision` only if replay requires it (question, pin) or it records the judgment's own provenance (verdict, timestamp). The same question from a different caller is the same judgment, so the audit event is envelope plus serialized Decision, or envelope plus error. The interpreter never sees who asked.

- **`Expand`'s question is a `SubjectSet`** (decided 2026-07-18): `Expand(SubjectSet subjectSet) → Result<Expansion>`. The resource#relation pair names exactly one relation's rewrite tree; there is no subject, because Expand asks who is in this set rather than whether one party is, so Contains's putative-question shape doesn't transfer. The optional kookie is the Read+Expand host's request field, consumed at the edge; evaluation context is constructor state.

- **`Expand` never recurses; depth exceeded is Contains-only** (decided 2026-07-18; leaf boundary explicit 2026-07-20, F10). It unfolds the queried relation's operator structure and crosses no reference, theory-side (`ComputedSubjectSet`) or fact-side (subjectset-valued members, factset substitution results); every reference materializes as an unexpanded leaf. Paper §2.4.5's tree shape settles it: if Expand inlined, a subjectset could never be a leaf. "Follows indirect references expressed through userset rewrite rules" is the contrast with Read, which cannot see that `viewer` includes `editor`; following means surfacing the references as nodes, not crossing into them. Work per call is bounded by theory shape times fact count at one level, never by chain length.

- **The over-specified and under-specified factset member errors apply to `Expand` unchanged** (decided 2026-07-18). The factset arm cannot stay a pure leaf, since without reading the facts under `resource#factset-relation` there is no pair to point a leaf at, so Expand performs the same single fact read and substitutes to emit leaves. Same three member shapes, same modeled errors, no silent skip.

- **Undefined namespace or relation mid-walk is Contains-only** (decided 2026-07-18; broadened to namespaces 2026-07-20). It arises only when the walk crosses into another relation's definition, and Expand never crosses: dangling references terminate as leaves, emitted as data without theory lookup. Such a leaf surfaces as an ill-formed question on the caller's re-expand, where it *is* the question. Emitting it is correct audit behavior, since the tree shows what the data contains.

- **Every error `Expand` meets is decisive — whole-call failure, no partial trees** (decided 2026-07-18). Kleene absorption exists because a boolean operand can dominate; a tree has no dominating value, so a broken branch always changes the answer. Partial trees with error-marker nodes were rejected under the result-channel ruling. Expand's error surface is undefined namespace, undefined relation on the question, over-specified factset member, under-specified factset member, fact lookup failed, snapshot unavailable, and ill-shaped direct member.

- **`Expansion` is the sibling result type, the same four-slot shape as `Decision`** (decided 2026-07-18; slot dropped 2026-09-08): `Expansion(SubjectSet, Tree, Kookie, Timestamp)`, with subjectset and tree in the question and verdict seats. Complete at birth, caller identity in the envelope, two clocks distinctly. Leaves are identities or subjectsets naming other (resource, relation) pairs; intermediate nodes are union, intersection, and exclusion. The tree DU's shape is design work, not a ruling.

- **The port is async and `ValueTask`-shaped, and the evaluators are async in consequence** (decided 2026-07-20; F11). The port is the domain's own declaration of its IO, and it has to tell the truth about what crosses the edge: fact lookup is network storage in the real adapter, so a sync port forces sync-over-async onto a hot path whose budget is milliseconds at high concurrency. The port is shaped for its worst legitimate adapter; in-process adapters conform, and `ValueTask` makes their synchronous completion nearly free. `Contains` and `Expand` await the port mid-walk, returning `ValueTask<Result<Decision>>` and `ValueTask<Result<Expansion>>`. `CancellationToken` flows through both and the port as mechanical plumbing: cancellation surfaces as an exception at the host edge, never as a modeled error. Not threading the token was rejected, since a cancelled request would keep walking the graph and paying for reads nobody wants. Parallel operand evaluation is out of scope; the first implementation is sequential short-circuiting, and the Kleene semantics are order-free precisely so parallelism can be added later without changing a verdict.

- **`Decision` does not carry the proof path.** The witness doesn't survive `!`: a true verdict under `(this | (parent, viewer)) ! banned` embeds a non-membership claim, and non-membership's only proof is the exhausted search. A path also costs hot-path allocation and leaks other subjects' memberships to any caller allowed to ask yes/no questions. "Why" is recomputed on demand by re-running `Contains` or `Expand` at the recorded snapshot ([[storage-versioning-design]]).

## Error conditions

Three families, nine conditions. Fact lookup failed and snapshot unavailable are the port's own error values; every other condition is a modeled error owned by `Kingo.Closures`. Every one is a `Result.Failure`. In Contains the Kleene rule decides whether an evaluation surfaces or absorbs it; in Expand every error is decisive. Depth exceeded and undefined namespace or relation mid-walk are Contains-only; Expand meets the rest. The ill-shaped direct member is numbered by arrival (2026-07-21) and sits beside the two factset member shape errors.

### Family 1 — the question is ill-formed against the theory

Caller defects, detectable before any I/O: the catalog at the pin is an in-memory value, so both checks are pure lookups. This family validates the set side only. The subject side is never theory-validated (ruled 2026-07-19; F9), because an `Identity` carries nothing theory-addressable — its namespace-shaped prefix is an opaque convention, and identity lives with authn.

1. **Undefined namespace.** The question's resource names a namespace the theory doesn't define: `Contains(io/document:readme#viewer@user:anne)` against a theory defining `doc`, not `document`. With no rewrite rule to interpret, the question isn't answerable *false*; it isn't answerable at all. A denial asserts "evaluated, and not a member" and replays at the snapshot; this asserts "no such set." Mapping it to `false` would turn every caller typo and version skew into silent denial, an outage that looks like policy.

2. **Undefined relation on the question.** The namespace exists but the relation doesn't: `Contains(io/folder:x#editor@user:anne)` when `folder` defines `owner`, `viewer`, `banned`, and `parent`. Same character as undefined namespace, kept distinct because the repair differs and so does the drift source — relation vocabularies evolve faster than namespace sets, so the typical cause is a caller compiled against a newer theory than the evaluator holds. This is the boundary the undefined-namespace-or-relation requirement draws: fail-closed applies to *facts*, never to theory drift or caller defects. `...` in the relation seat is unrepresentable (ruled 2026-07-21, inverting F18's undefined-relation-by-contract ruling of 2026-07-20): `...` is not a relation, the exactly-specified factset member is a `ResourceFact` carrying a bare `Resource`, and `RelationName` loses the `Nothing` sentinel ([[resource-fact-case]]). `SubjectSet` has no `Parse`, so no parse edge exists that could refuse `io/folder:y#...`, and there is no refusal test to pin.

### Family 2 — the evaluation couldn't complete

Defects in the graph, or in its interaction with the depth bound. These surface mid-walk, after I/O has begun.

3. **Depth exceeded** (Contains only). The walk hit the constructor-configured bound. The unit is the fact-driven re-entry (ruled 2026-07-18): each factset hop and each subjectset-valued member expansion consumes one, while `ComputedSubjectSet` crossings are free, being acyclic by construction and unable to recurse without consuming a fact. The bound can't be computed at design time because the recursion is bound by the *facts*, not the theory, whose rewrite tree is finite and known at parse: a factset like `(parent, viewer)` re-enters the walk once per stored parent fact, and subjectset-valued members re-enter once per nesting level. Chain length is whatever users have written: `io/folder:a#parent@io/folder:b`, `io/folder:b#parent@io/folder:c`, arbitrarily long, or a cycle back to `a`. The bound is an operational guard against user-writable data, and the error carries it so audit can distinguish a data cycle from a bound set too low.

4. **Undefined namespace or relation encountered mid-walk** (Contains only; Expand emits the dangling reference as a leaf; broadened 2026-07-20, F8). Same surface as the two ill-formed-question conditions, a different defect: theory/data drift, and the error records which lookup failed. Under theory v1, `io/doc:x#viewer@org/group:eng#member` is valid and stored; theory v2 removes `member` on `group`, or the namespace, and the fact remains. Factset-resolved resources with undefined namespaces land here too. Both producers are closed at the write edge, so with evaluation reading the catalog and the graph at one `Kookie` this is a never-in-practice backstop with the same standing as the factset member shape errors. A pin past the retention horizon fails as snapshot unavailable instead. Treating the dangling reference as an empty set was rejected: it silently changes outcomes under `!`, where an undefined `banned` would mean nobody is banned.

5. **Factset member over-specified.** Traversal met a `SubjectSetFact` member, `io/folder:x#parent@io/folder:y#viewer`, where the exactly-specified shape is the `ResourceFact` member `io/folder:y#...` ([[resource-fact-case]]). No override semantics, no silent skip.

6. **Factset member under-specified.** Traversal met a `SubjectFact` member, `io/folder:x#parent@io/folder:y` or `@user:anne`: a legal fact carrying no resource for the pair's second element. Distinct code from the over-specified member; same family, same upstream Write-path guard.

9. **Member ill-shaped for direct expansion** (ruled 2026-07-21; [[resource-fact-case]]). Direct-membership expansion (`this`, the direct-membership requirement) met a `ResourceFact` member, `io/doc:x#viewer@io/folder:y#...` — a resource where a subject or subjectset belongs, the mirror of the under-specified member. The shape is meaningful only under factset consumption: the Subject/Resource split makes identity-matching a resource a category error, and the paper assigns `#...` no meaning outside factsets. Never skipped, never identity-matched; a resource meant as a direct member is spelled `io/doc:x#viewer@io/folder:y`. Refused upstream by the same Write-path member-shape guard as the factset member shape errors, with the same never-in-practice standing. Applies to Contains and Expand alike, since Expand meets it materializing `this` members.

### Family 3 — the context broke

Infrastructure failures, surfaced through the port and propagated untranslated: a wrapper adds a layer without adding a fact.

7. **Fact lookup failed.** The pinned port's I/O failed outright.
8. **Snapshot unavailable.** The pin points beyond the retention window, or cannot be served — the audit-replay horizon from [[storage-versioning-design]].

### Deliberately absent

- **Theory cycles** (mutual computed subjectsets) are unrepresentable: `Namespace.Create` rejects them at construction, so Contains carries no theory-cycle guard (ruled 2026-07-18; [[namespace-create-validation]]). The zero-fact recursion graph is the `ComputedSubjectSet` references, intra-namespace by construction since the type carries only a `RelationName` and roots at the same resource; factset arms consume a fact, so they count depth instead. Dangling intra-namespace references are rejected in the same pass. The guard lives in construction rather than document parse, because the Write API builds `Theory` values without touching `Kingo.Documents`. Implemented 2026-07-21: duplicate, dangling-reference, and cycle checks, with `namespace.rewrite_cycle` errors carrying the full cycle path.
- **Timeout and cancellation** are host-edge concerns, not domain errors the algebra models.
- **Rewrite-tree depth** is bounded at construction (`SubjectSetRewrite.MaxDepth`, refused as `rewrite.depth`), so operator recursion over a theory is stack-safe without an evaluator guard. The depth bound meters facts only.

## Requirements

1. The result is a **`Decision`** (`Kingo.Closures`, stub exists), not a bare bool: question, verdict, the snapshot it was evaluated against, timestamp. The audit event is the host's request envelope plus this value serialized ([[authz-event-logging]]); the timestamp comes from an injected `System.TimeProvider`. Expand's sibling is **`Expansion`**, the same four-slot shape carrying the tree (stub exists).
2. Direct membership (`this`) includes **both** direct subject facts **and** the members of subjectset-valued facts stored under the same `SubjectSet` — Zanzibar's userset-expansion clause. A grant to `org/group:eng#member` must make every member of that set a member here. A `ResourceFact` member here is the ill-shaped direct member error.
3. Contains's walk is **cycle-safe and depth-bounded with a modeled outcome**, a `Result` error and never a crash. Graph data is user-writable and can hold parent loops, so an uncrashable hot path is a security property. Theory cycles are unrepresentable, so the walk carries no theory-cycle guard; Expand needs no bound.
4. Evaluating against an **undefined namespace or relation is a modeled error**, distinct from a denial. Fail-closed applies to facts, not to theory drift or caller defects.
5. The only I/O is **fact lookup, injected as a port**, the first genuine port family, handed to the interpreter already **snapshot-pinned** so one Check evaluates against one consistent snapshot end to end. The zookie enters the *host API's* signature as an opaque token, consumed at the edge ([[storage-versioning-design]]). Two implementations by design: Check's cached and hedged one, Read+Expand's plain one.
6. The access patterns this work discovers are the **input to the store's key design** ([[storage-versioning-design]]). Expected at minimum: point lookup and range read over `resource#relation`. Record what Expand adds in [[fact-store-access-patterns]], a note seeded when design starts and the deliverable this requirement names (decided 2026-07-20; F19). Whether the port surfaces those as two operations or one filtered range read is the clean-room's choice; this pins the patterns, not the operation count (assigned 2026-07-20; F20). The evaluator needs no reverse lookup ("which sets contain subject X"), deliberate and confirmed. The drift ruling adds one cold-path shape outside the evaluator: the theory-write guard's reverse existence query (F8).
7. **Exclusion and intersection semantics are settled as Kleene absorption, and must be pinned by tests.** Evaluation order is a cost choice precisely because the semantics are order-free. The theory-document example's `banned` exclusion ([[theories]]) is the obvious fixture, including its decisive and absorbed error cases.
8. **Factset traversal** (`FactToSubjectSet`) **is settled (exactly specified traverses, over- and under-specified members are modeled errors) and must be pinned by tests** covering all three member shapes.
   - *Unverified hypothesis, worth testing during design (2026-07-16, a naming exercise's side effect, not a decision):* the rename to `FactToSubjectSet(FactsetRelation, ComputedSubjectSetRelation)` asserts the second component is *the same construct* as `ComputedSubjectSet`, rooted at each resource the walk resolves rather than at this resource — Zanzibar's own structure (`computed_userset` nested inside `tuple_to_userset`). If it holds, the `FactToSubjectSet` arm delegates per resolved resource instead of reimplementing, and this requirement's decision is forced rather than chosen. Check whether rooting is really the *only* difference; the `ResourceFact` member is where it could break, since a bare resource has no relation of its own.
9. **Audit emission is an effect at the host edge.** The interpreter returns the `Decision` and never sees a sink, a logger, or a clock it didn't receive.
